## 1. 产品定位与本次边界

### 1.1 一句话定位

FLM 是位于「行动执行」之后、「再规划」之前的**闭环能力中枢**：把一次任务的真实结果（用户评价 + 运行日志 + 环境变化）转成结构化反馈事件，经三层评价与失败归因，沉淀为可复用的经验与策略版本，并通过灰度放量安全地作用于下一次任务。

### 1.2 本仓库现状（侦察结论）

落地前先摸清了既有能力，**避免重复造轮子**。关键事实（均带证据）：

| 既有能力 | 位置 | 与 FLM 的关系 |
|---|---|---|
| 完整任务轨迹落库（粗粒度 DAG + 原子步骤 + 工具 I/O） | `chat_trace_nodes` / `trace_steps` / `trace_tool_calls`（`src/chat-trace-persist.ts`） | **复用为 TaskTrace**，不新建轨迹表 |
| 向量化与相似度检索 | `src/embedding.ts`（`embedText` / `cosineSim` / `float32ToBuffer`） | **复用**为经验记忆的索引底座 |
| 多维评分引擎（确定性断言 + LLM Judge + 置信度聚合） | `src/eval-center/eval-scoring.ts` | **不复用、不重写** —— eval-center 评的是 golden test case，FLM 评的是线上真实任务，输入与结论语义不同。FLM 的评价引擎聚焦「三档结论 + 归因到环节」，这是 eval-center 没有的 |
| Harness 清单版本化 + promote/rollback | `src/harness-registry.ts`（`harness_versions`） | **不复用** —— 其版本单元是 harness manifest（system prompt + subagents + tools + skills），FLM 的策略单元是 prompt 模板 / 路由规则 / 参数模板 / few-shot 样例，且 FLM 需要**灰度放量**（harness 只有全量翻转） |
| 经验教训（per-run lesson） | `src/autonomy/autonomy-learning.ts`（`autonomy_lessons`） | **不复用** —— 其单元是「单次运行的教训文本」，无 positive/negative 样本类型、无归因环节、无复用计数。FLM 的 CaseRecord 语义更完整 |
| 审计表族 | `auth_audit_log` / `tool_call_audit_log` / `billing_audit_log` | **复用命名与保留策略**，FLM 自己的策略审计另建表（原子性要求不同） |
| 用户对消息的评价 | **不存在**（`messages` 表无任何评价列，`MessageBubble.tsx` 无评价按钮） | **本模块新建** —— 这是 FLM 最大的一块空白 |
| 失败归因到具体环节 | **不存在**（仅有 harness 的「新增失败用例集合」与 trace 的 `status='error'`） | **本模块新建** |
| 灰度放量（canary / 百分比） | **不存在**（全仓库无 canary / 灰度 / 百分比放量概念） | **本模块新建** —— 现有 promote/rollback 全是全量原子翻转 |

> 结论：FLM 的**独占价值**是 ①消息级用户反馈通道 ②三类来源统一归一化 ③三层评价与失败归因 ④正负样本经验记忆 ⑤带灰度的策略版本闭环 ⑥运营控制台。**其余一律复用既有底座，不重复实现。**

### 1.3 本次目标

| 编号 | 目标 |
|---|---|
| G1 | 建立覆盖**用户反馈 / 系统日志 / 环境数据**三类来源的统一采集能力 |
| G2 | 建立**统一分析框架**，把异构反馈归一化为同一事件模型与评价维度 |
| G3 | 建立**结果层 / 过程层 / 质量层**三层评价引擎，并把失败归因到具体环节 |
| G4 | 建立学习链路：短期纠偏、中期经验沉淀、长期策略优化与数据回流 |
| G5 | 建立**带灰度与自动回滚**的闭环执行机制 |

### 1.4 与原文的口径差异（Think Before Coding：显式暴露取舍）

| 原文口径 | 本次口径 | 理由 |
|---|---|---|
| 「支持亿级日写入」「千万级向量检索」 | 不承诺压测绝对值；实现为**可配置采样 + 索引 + 分页**，并在报告中标为「未压测」 | 单机 dev 实例无法产生亿级数据，承诺绝对值即为不可验证的过度承诺 |
| 「跨租户隔离」 | `tenant_id` 字段**预留并落库**，隔离边界落在**用户 / 会话**级（与平台现有隔离模型一致） | 本平台无显式租户实体（侦察确认），凭空造一个租户体系属于过度设计 |
| 「LLM-as-Judge 与规则判定双轨」 | **规则轨道必须可用且为默认**；LLM 轨道为**可选**（每次评价显式开启），不可用时降级为单轨并如实标注 `evaluator` | 保证验收可复现、不依赖外部模型网络；也符合原文「降级」要求 |
| 「数据集回流模型训练平台」 | 产出**落库 + 可导出**的偏好数据集与 SFT 语料，带来源与生成时间；**不实现**训练平台对接 | 原文 1.4 非目标已明确「不自建训练基础设施，仅产出数据集」 |
| 「环境数据采集」全量快照 + 增量订阅 | 实现**观测点注册 + 前后快照 diff + 有效期**；不实现对外部业务系统的实时订阅连接器 | 原文 1.4 非目标明确「不改造业务系统内部流程，仅通过开放接口读取」；连接器需业务侧契约，属依赖项 |

## 2. 术语与概念模型

| 术语 | 定义 |
|---|---|
| **FeedbackEvent** | 一次反馈的最小结构化记录单元，三类来源（user / system / env）统一映射为该模型 |
| **TaskTrace** | 一次任务的执行链路记录，本模块复用既有 `chat_trace_nodes` / `trace_steps` / `trace_tool_calls` |
| **结果层** | 评价「任务目标是否最终达成」，输出 `achieved / partial / failed` 三档 |
| **过程层** | 评价「是否按预期步骤推进、何处异常」，输出路径符合度、步骤耗时、重试次数、首个异常点 |
| **质量层** | 评价「输出是否满足要求」，六维：事实性 / 格式合规 / 响应时延 / 成本消耗 / 安全合规 / 用户偏好匹配 |
| **失败归因** | 把失败定位到 `intent / planning / tool_selection / param_gen / execution / summary` 六个环节之一 |
| **策略版本** | 可灰度、可回滚的 `prompt / routing / param / fewshot` 组合快照 |
| **经验记忆** | 沉淀成功（positive）与失败（negative）轨迹形成的、可向量检索复用的案例库 |
| **灰度放量** | 新策略按比例 / 按智能体 / 按会话逐步生效，劣化则自动回滚 |

**概念模型一句话**：多源反馈经统一分析框架归一化后，进入三层评价分析，产出评价与归因结论，再由学习层转化为策略更新，最终通过闭环执行层（门禁 → 灰度 → 放量/回滚）作用于下一次任务。

## 3. 功能需求 · 验收标准 · 测试用例

> 约定：**验收标准**是该功能点做到什么算对；**测试用例**是浏览器可执行、可截图存证的步骤。
> 用例编号 `TC-FLM-xx` 与 `docs/test_report/feedback-learning-module/` 中的报告逐条对应。

### 3.1 F1 反馈采集层

#### F1.1 用户反馈采集

**功能描述**：采集终端用户对智能体输出的主观评价。

**需求点**
- 显式反馈：点赞 / 点踩、1–5 分评分、采纳或否决、纠错文本、补充要求。
- 隐式反馈：重复提问、指令改写、会话静默放弃（行为信号）。
- 结构化补充：点踩时勾选原因标签（答非所问 / 事实错误 / 格式不符 / 过于冗长 / 未完成任务 / 其他）。
- 上下文绑定：每条反馈必须绑定 `task_id` / `trace_id` / `session_id` / `step_id`，并快照当时的输入与输出。
- 入口形态：Web 端轻量组件 + 服务端 API 两种接入方式。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F1.1.1 | 聊天消息气泡上可对助手消息点赞 / 点踩，操作后状态即时回显 |
| AC-F1.1.2 | 点踩时必须可勾选原因标签（六选一或多选），并可选填纠错文本 |
| AC-F1.1.3 | 单条反馈提交后 **≤5 秒**内可在 FLM 控制台「反馈流」查询到 |
| AC-F1.1.4 | 反馈落库时带 `task_id` / `trace_id` / `session_id` 可用则填充，缺失时以 `session_id + 消息时间` 兜底对齐，**绑定成功率 100%**（可对齐即绑定，不可对齐则显式标记 `alignment='fallback'`） |
| AC-F1.1.5 | 同一用户对同一消息的重复评价为**更新**而非新增（幂等） |
| AC-F1.1.6 | 反馈提交**不阻塞**聊天主链路：接口失败不影响消息收发 |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-02 | 登录 → 工作台 → 对一条助手消息点赞 | 按钮高亮；控制台可查到该条 `type=explicit_like` |
| TC-FLM-03 | 对一条助手消息点踩 → 勾选「未完成任务」→ 填纠错文本 → 提交 | 提交成功；控制台可查到 `type=explicit_reject` 且 `reason_tags` 含「未完成任务」 |
| TC-FLM-04 | 打开 FLM 控制台「反馈流」 | 上述反馈在列，且显示来源、类型、置信度、绑定状态 |
| TC-FLM-05 | 查看该反馈详情 | 显示绑定的 session / trace / step 与输入输出快照 |

#### F1.2 系统日志采集

**功能描述**：采集智能体运行过程中产生的客观结构化执行记录。

**需求点**
- 采集范围：工具调用回执、错误码、耗时、重试次数、链路 trace、Token 消耗。
- 采样：默认全量采集；支持配置采样率与字段白名单。
- 结构化：进入归一化层前完成字段抽取与类型标准化。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F1.2.1 | 可从既有 `trace_tool_calls` / `trace_steps` 订阅并产出 `source='system'` 的 FeedbackEvent |
| AC-F1.2.2 | 采集支持**采样率**（0–100%）与**字段白名单**配置，改动即时生效 |
| AC-F1.2.3 | 工具调用失败（`status != 'ok'`）产出的反馈事件带 `error_code` 与 `stage` |
| AC-F1.2.4 | 采集失败不影响主链路（异常吞掉并记日志，主流程继续） |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-06 | 控制台触发「订阅系统日志」 | 产出若干 `source='system'` 事件，列表可见工具名/耗时/状态 |
| TC-FLM-07 | 把采样率调到 0% 再触发 | 不再产出新事件；调回 100% 后恢复 |

#### F1.3 环境数据采集

**功能描述**：采集行动执行前后外部环境的真实变化。

**需求点**
- 观测点注册：业务侧可注册关键状态字段作为观测点。
- 快照 diff：任务前后快照对比，判定行动是否真正生效。
- 时效性：快照带时间戳与有效期，过期数据不参与判定。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F1.3.1 | 可自助注册观测点（名称 + 取值路径 + 期望值） |
| AC-F1.3.2 | 可提交前后快照并计算 diff，产出「达成 / 未达成」判定 |
| AC-F1.3.3 | 过期快照（超过有效期）不参与判定，事件标记 `expired=true` |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-08 | 「设置 → 环境观测点」注册一个观测点 | 列表出现该观测点 |
| TC-FLM-09 | 提交一组前后快照 → 触发 diff | 产出 `source='env'` 事件，含 diff 结果与判定 |

### 3.2 F2 统一分析框架（归一化层）

**需求点**：统一事件模型 / 实体对齐 / 时序对齐 / 冲突消解与置信度 / 去重 / 脱敏。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F2.1 | 三类来源全部映射为同一 `FeedbackEvent` Schema（字段一致，来源差异进 `raw_payload`） |
| AC-F2.2 | 实体对齐按 `task_id / trace_id / session_id / step_id` 四级主键；缺失时按时间+内容兜底并标记 |
| AC-F2.3 | 时序对齐：事件按时间重建时间线，乱序输入可正确排序 |
| AC-F2.4 | 冲突消解：用户反馈与系统日志冲突时按**来源权重 × 置信度**加权，策略参数可配置 |
| AC-F2.5 | 去重：同来源同时刻重复事件按时间窗去重，一次行为不重复计分 |
| AC-F2.6 | 脱敏：归一化阶段完成手机号 / 身份证 / 银行卡 / 邮箱 / Token 五类识别与脱敏，**规则可热更新** |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-10 | 触发一次归一化 | 三类来源事件均进入统一事件流，字段齐全 |
| TC-FLM-11 | 查看脱敏结果 | 含手机号/邮箱的原文在事件中被替换为掩码，且 `desensitized=true` |
| TC-FLM-12 | 在「设置 → 脱敏规则」新增一条规则后重跑 | 新规则即时生效（热更新），无需重启 |

### 3.3 F3 三层评价分析引擎

**需求点**：结果层三档判定 / 过程层路径与异常 / 质量层六维 / 归因到环节 / 评价可解释。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F3.1 | 结果层输出 `achieved / partial / failed` 三档，且给出判定依据 |
| AC-F3.2 | 结果层支持双轨：规则轨（默认）+ LLM 轨（可选开启）；两轨结论不一致时标记进入**人工复核队列** |
| AC-F3.3 | 过程层输出路径符合度、步骤耗时、重试次数、**首个异常步骤** |
| AC-F3.4 | 质量层输出事实性 / 格式合规 / 响应时延 / 成本消耗 / 安全合规 / 偏好匹配六维分数 |
| AC-F3.5 | 未达成或质量不达标时，归因到 `intent / planning / tool_selection / param_gen / execution / summary` 之一 |
| AC-F3.6 | **每个结论附带证据片段**（引用的反馈原文 / 日志行 / 环境 diff），可解释率 100% |
| AC-F3.7 | 单任务三层评价耗时 ≤ 10 秒（本地实测，记入报告） |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-13 | 控制台对一批任务触发三层评价 | 结果层三档分布、过程层指标、质量层六维均产出 |
| TC-FLM-14 | 打开任一评价详情 | 显示归因环节 + 证据片段（可点击跳转来源） |
| TC-FLM-15 | 打开「人工复核队列」 | 双轨不一致的评价进入该队列 |

### 3.4 F4 学习与自进化层

**需求点**：短期纠偏 / 经验记忆 / 策略优化 / 数据回流 / 知识库自更新。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F4.1 | 短期纠偏支持配置重试次数上限、退避规则、切换工具白名单；超限终止并**降级为人工介入** |
| AC-F4.2 | 短期纠偏记录耗时，**不得导致任务耗时超过原任务 2 倍**（超限即停止重试） |
| AC-F4.3 | 经验记忆：成功轨迹入 positive、失败轨迹入 negative，支持**向量检索 Top-K** |
| AC-F4.4 | 案例检索 Top5 命中率 ≥ 80%（用标注命中集合实测，记入报告） |
| AC-F4.5 | 策略优化产出四类策略版本（prompt / routing / param / fewshot）并带**自动更新建议** |
| AC-F4.6 | 数据回流产出 chosen/rejected 偏好对与 SFT 语料，**每条带来源与生成时间**，可导出 |
| AC-F4.7 | 知识库自更新：纠错类反馈生成知识条目候选，**经审核后**才写入知识库 |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-FLM-16 | 触发短期纠偏 | 生成纠偏动作记录，含重试次数与耗时；超限时状态为「已降级人工」 |
| TC-FLM-17 | 控制台「案例库」输入一个目标做检索 | 返回 Top-K 相似案例，含正负样本类型与相似度 |
| TC-FLM-18 | 从归因结论生成策略建议 | 产出策略版本草稿，关联归因标签 |
| TC-FLM-19 | 生成数据回流产物 | 产出偏好对与 SFT 语料，每条含来源与生成时间，可下载 |
| TC-FLM-20 | 对纠错反馈生成知识条目候选 → 审核通过 | 候选进入知识库，状态变为已采纳 |

### 3.5 F5 闭环执行与安全机制

**需求点**：策略版本管理 / 回归评测门禁 / 灰度发布 / 自动回滚 / 人工审核 / 全链路审计。

**验收标准**
| 编号 | 标准 |
|---|---|
| AC-F5.1 | 每次策略变更生成新版本，记录变更内容、触发来源（自动/人工）、关联归因标签、父版本 |
| AC-F5.2 | 版本上线前必须过**回归评测门禁**；任一核心指标劣化超阈值即**拦截**，并给出劣化明细 |
| AC-F5.3 | 灰度支持**按流量比例**（最小 1%）放量，比例可调 |
| AC-F5.4 | 灰度期核心指标劣化超阈值 → **自动回滚**到上一稳定版本并告警，回滚从触发到生效 ≤ 60 秒 |
| AC-F5.5 | 涉及安全合规的策略变更标记为**强制人工审核**，未审核不可放量 |
| AC-F5.6 | 全链路审计：每次生成 / 发布 / 放量 / 回滚均留痕，支持按时间线回放 |

**测试用例**
| 用例 | 步骤 | 期望 |
|---|---|---|

| TC-FLM-22 | 提交一个合格版本 → 灰度 10% | 版本状态 `canary`，灰度比例 10% 生效 |
| TC-FLM-23 | 调整灰度比例 10% → 100% | 版本状态 `released`，比例 100% |
| TC-FLM-24 | 对灰度中版本触发指标劣化 → 自动回滚 | 版本状态 `rolled_back`，上一稳定版本恢复生效，审计留痕 |
| TC-FLM-25 | 查看审计时间线 | 上述生成/拦截/放量/回滚动作按时间线完整可回放 |

## 4. 数据模型

全部落在**主数据库**（SQLite / PostgreSQL 双兼容），遵循 `docs/howto/modify-db-schema.md`。

| 表名 | 对应原文实体 | 说明 |
|---|---|---|
| `flm_feedback` | —— | 用户反馈原始记录（显式 + 隐式），消息级，提交即落库 |
| `flm_events` | **FeedbackEvent** | 归一化后的统一反馈事件（三类来源） |
| `flm_evaluations` | **EvalResult** | 三层评价结果 + 归因 + 证据 |
| `flm_cases` | **CaseRecord** | 经验记忆案例（positive / negative） |
| `flm_strategies` | **StrategyVersion** | 策略版本（含灰度状态与门禁报告） |
| `flm_actions` | **FeedbackAction** | 闭环动作记录（retry / replan / strategy_update / rollback） |
| `flm_observations` | —— | 环境观测点注册 |
| `flm_snapshots` | —— | 环境前后快照与 diff |
| `flm_config` | —— | 模块配置（采样率、字段白名单、重试策略、脱敏规则、告警阈值、降级开关） |
| `flm_alerts` | —— | 告警记录 |
| `flm_audit` | —— | 策略全链路审计 |

**TaskTrace 不新建表**，直接复用 `chat_trace_nodes` / `trace_steps` / `trace_tool_calls`。

### 4.1 FeedbackEvent 字段

`event_id, source(user|system|env), task_id, trace_id, session_id, step_id, chat_jid, type, raw_payload, normalized_payload, confidence, alignment(direct|fallback), dedup_key, desensitized, tenant_id, occurred_at, created_at`

### 4.2 与原文的字段差异

原文 `FeedbackEvent` 无 `chat_jid` / `alignment` / `dedup_key` / `occurred_at` —— 是本仓库落地必需的补充：
- `chat_jid`：平台会话主键，缺失则无法与 `messages` / trace 关联
- `alignment`：原文要求「缺失主键时兜底关联」，需显式记录用了哪条路径，否则无法审计对齐质量
- `dedup_key`：F2.5 去重的落点
- `occurred_at` vs `created_at`：时序对齐（F2.3）必须区分「事件发生时间」与「入库时间」，否则乱序修正无从谈起

## 5. 非功能需求（本次口径）

| 类别 | 要求 | 本次落地方式 |
|---|---|---|
| 性能 | 反馈提交到可查询 ≤ 5 秒 | 同步落库，无异步队列（AC-F1.1.3 实测验证） |
| 性能 | 单任务三层评价 ≤ 10 秒 | 纯规则计算，无外部调用（AC-F3.7 实测验证） |
| 可靠性 | 采集失败不影响主链路 | 所有 FLM 调用点 try/catch 隔离（AC-F0.2） |
| 降级 | 一键开关，降级为「无反馈执行」 | `flm_config.enabled` 开关（AC-F0.1） |
| 安全 | 反馈数据默认脱敏；策略变更需鉴权 | 归一化阶段强制脱敏；控制台接口 admin-only |
| 隔离 | 按用户/会话隔离 | 反馈与控制台按登录用户 + admin 角色隔离 |
| 成本 | LLM 调用支持开关与采样 | LLM 轨默认关闭，单次评价显式开启 |
| 容量 | 亿级写入 / 千万级向量 | **不承诺**，见 §1.4；实现分页与索引 |

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 用户反馈主观噪声误导学习 | 置信度模型 + 来源权重；策略变更强制过门禁（F5.2） |
| LLM-as-Judge 偏差与成本 | 规则轨为默认且独立可用；LLM 轨可关闭；双轨不一致进人工复核 |
| 自动策略更新导致线上劣化 | 门禁 + 灰度 + 自动回滚三重保护（F5） |
| 环境数据涉敏 | 归一化阶段强制脱敏，规则可热更新（F2.6） |
| **FLM 自身故障拖垮主链路** | 一键降级开关 + 全调用点异常隔离（F0） |
