1. Bug 根因分析

Bug 1（最关键）：getSkillContents 只查 DB，用户技能存在磁盘

根因：applyTurnMounts() 调用 getSkillContents(ids) 查询 DB skills 表，但用户创建的技能存储在磁盘 SKILL.md 文件中，不在 DB 里。只有 builtin 技能在 DB。

修复：新增 getSkillContentsForTurn(ids, userId) 函数，DB 查询未命中时从磁盘 getSkillContentPath 读取 SKILL.md 内容。

Bug 2：WebSocket handler 丢弃 selectedMounts

根因：WS send_message handler 构建校验对象时不含 selectedMounts 字段。

修复：safeParse 加 selectedMounts，解构后传给两个 handler。

Bug 3：handleAgentConversationMessage 不桥接 mounts

根因：函数签名有 selectedMounts 参数但从不调用 setPendingTurnMounts，冷启动 processAgentConversation popPendingTurnMounts 永远返回 undefined。

修复：在 storeMessageDirect 后调 deps.setPendingTurnMounts(messageId, opts.selectedMounts)。

Bug 4：IPC 注入路径不支持 per-turn mounts

根因：当 agent 已活跃时，queue.sendMessage 只通过 stdin 注入文本，mounts 只在冷启动时通过 ContainerInput 应用。

修复：当 hasTurnMounts 为 true 时，跳过 IPC 注入（返回 'no_active'），走冷启动路径。processAgentConversation 从 DB 回放消息不丢失上下文。

Bug 5：Agent 子对话无 ChatToolbar

根因：ChatView.tsx agent 子对话分支（780 行）只渲染 MessageList + MessageInput，无 ChatToolbar。

修复：在 MessageList 和 MessageInput 之间插入 ChatToolbar。

Bug 6：sendAgentMessage 不传 selectedMounts

根因：sendAgentMessage 通过 WS 发送 { type, chatJid, content, agentId, attachments }，不含 selectedMounts。

修复：加 selectedMounts? 参数，WS 消息体含 selectedMounts。ChatView agent 子对话 onSend 读 useChatMountsStore 传入。
