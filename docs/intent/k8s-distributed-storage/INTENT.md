# 意图文档：K8s 分布式存储改造

## 日期
2026-09-14

## 用户原始需求

> "用户管理，分组，会话，消息，工作区产物等等，系统的全部存储，都必须存储到云端数据库postgreSQL， minIO， redis等"
> "deepthink 系统的设置，配置，等等都必须存储到数据库postgreSQL里，因为是部署到k8s 云端集群， 必须要做分布式系统改造支持"

## 意图解析

DeepThink 当前部署在本机 K8s kind 集群（2 Pod），使用 RWO PVC 挂载本地文件系统。系统存在大量文件级存储（JSON配置文件、工作区文件树、会话状态、IPC队列等），这些文件在多 Pod 环境下无法共享，导致：

1. **配置不同步**：Pod A 通过 Web UI 保存的配置（飞书/模型服务商/系统设置/外观等），Pod B 读取不到
2. **工作区不可达**：Agent 容器挂载的工作区文件在单个 Pod 上，其他 Pod 无法访问
3. **IPC 消息丢失**：Agent Runner 与主服务的消息队列是本地文件目录
4. **会话状态不一致**：Claude SDK 的会话恢复数据在本地文件

## 目标

将 DeepThink 全部持久化存储从本地文件迁移到云原生基础设施：
- **PostgreSQL**：所有结构化配置、元数据、消息、用户、会话
- **MinIO**：工作区文件、产物、版本快照、回收站、Trace I/O 大对象
- **Redis**：IPC 消息队列、流式缓冲、会话临时状态、分布式锁（已有）

## 验收标准

1. 所有配置（21个域）通过 Web UI 保存后，任意 Pod 能读取最新值
2. 工作区文件能跨 Pod 读写
3. Agent 输入输出跨 Pod 可达
4. 飞书消息正常收发
5. 前端对话流式输出正常
6. 技能加载执行正常
7. 系统 25 项核心功能回归通过
