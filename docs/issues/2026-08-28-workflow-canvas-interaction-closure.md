# 2026-08-28 工作流画布无法拖放与手工连线

## 1. 用户现象

进入「工作流」新建页后，中间区域虽然显示空画布提示，但拖拽节点无法形成稳定的可编辑画布；React Flow 的缩放控件和小地图不可见。即使画布已有节点，自定义节点卡片也没有输入/输出连接点，无法按页面提示“从节点边缘拉线连接”。

## 2. 问题描述

工作流编辑页的核心手工编排链路不完整：空画布无法可靠接收节点，节点之间无法建立边，缩放或平移后拖入节点的位置也会偏离鼠标落点。因此用户无法从空白状态完成“添加节点 → 连线 → 保存”的最小闭环。

## 3. 根因

1. `WorkflowEditorCanvas` 根节点使用 `flex-1`，但它的直接父元素不是 flex 容器。React Flow 自身使用绝对定位并依赖父容器的明确尺寸，最终根节点高度计算为 `0`。
2. 自定义 `WorkflowNodeCard` 没有渲染 React Flow 的 `Handle`。仅设置 `nodesConnectable` 不会自动给自定义节点生成连接点。
3. 拖放位置直接用浏览器坐标减容器边界计算，没有经过 React Flow 的 viewport 变换；缩放或平移后坐标不再对应流程坐标。

## 4. 复现路径

1. 启动最新版前后端并登录。
2. 打开「工作流」菜单，停留在新建工作流。
3. 检查 `.react-flow` 的边界：高度为 `0`，页面上没有缩放控件和小地图。
4. 从左侧拖入两个节点；无法在节点边缘找到可拖动的连接点，也就不能建立边。

## 5. 诊断方法

- 在浏览器中读取 `.react-flow`、`.react-flow__renderer` 和 `.react-flow__pane` 的 `getBoundingClientRect()`，三者高度均为 `0`。
- 检查自定义节点源码及运行时 `.react-flow__handle` 数量，确认没有 `Handle`。
- 对照 React Flow 坐标 API，确认当前 `onDrop` 未调用 `screenToFlowPosition`。

## 6. 修复方案

- 将画布 wrapper 改为 `h-full min-h-0 relative`，继承三栏布局已经确定的高度。
- 为普通节点渲染左右两个连接点；开始节点仅提供输出连接点，结束节点仅提供输入连接点。
- 在 `onInit` 保存 React Flow 实例，拖放时先调用 `screenToFlowPosition`，再按节点尺寸把卡片中心对齐鼠标落点。
- 抽取坐标投影和连接点方向规则为纯函数，并补充单元测试。

## 7. 处理卡住的状态（如适用）

不适用。问题发生在尚未创建运行实例的编辑阶段，不涉及需要清理的工作流运行态。

## 8. 经验沉淀 / 预防

- React Flow 容器必须沿父级高度链拿到明确高度；`flex-1` 只在直接父级是 flex/grid 布局时才有效。
- 自定义节点的可连线能力由 `Handle` 提供，`nodesConnectable` 只是全局开关。
- 浏览器坐标不能直接当作画布坐标，涉及缩放/平移的交互必须使用库提供的 viewport 投影 API。
- 后续前端端到端测试应至少覆盖：空画布拖入两个节点、建立连接、保存、重新打开后节点和边仍存在。
