## 🔌 工作台隐藏引擎切换区

聊天头部的引擎切换区（Claude / AtomCode / Codex / OpenCode / pi 五个按钮）不再展示：

- `EngineSwitcher` 组件整体删除（99 行），`ChatView` 里的引用一并移除；
- **引擎配置入口统一收进设置页子菜单**：AtomCode / Codex / OpenCode / pi 各自的引擎配置，
  外加「引擎」总入口——聊天头部临时切换与设置页长期配置两套入口收敛成一套；
- **群组引擎链路完全不受影响**：`chat` store 的 `switchEngine` 保留不动，后端
  `RegisteredGroup.engine` 与 5 个引擎 adapter（claude / atomcode / codex / opencode / pi）的
  分发逻辑零改动，只是不在聊天头部提供切换按钮。

> 判断某个群组实际跑哪个引擎，仍然是查 `registered_groups` 表里该行的 `engine` 值（见
> `CLAUDE.md` §2.0 ①），与本次界面调整无关。

## 📦 安装与升级

- **Windows**：下载 `DeepThink-Setup-1.8.2.exe` 覆盖安装；已装旧版本的用户会**自动静默更新**
  （后台下载 → 备份配置到 `%APPDATA%\DeepThink\backups` → 重启安装）。
- **macOS / Linux**：对应 `.dmg` / `.AppImage`。
- 升级前的配置备份保留 3 份以内可自行清理；数据目录（`%APPDATA%\DeepThink\data`）不受升级影响。
- 桌面版版本号 `1.8.2`（`desktop/package.json`），与 tag / 发布线同号，
  本地 `scripts/pack-win.ps1 -Version 1.8.2` 打包同号。

## ✅ 测试基线

本次发布 commit 本身**零代码改动**（仅 `CHANGELOG.md` + 本文件 + `desktop/package.json` 版本号），
功能代码全部落在已推送的 `1bb4267`，故本版不存在"新改动引入回归"的空间。以下为该代码状态的实测基线：

- 全量 vitest：**189 文件 / 2530 用例 —— 2501 passed / 15 failed / 14 skipped**（18.5s）
- **15 个失败全部是本机 Windows 环境噪音**，与既有基线逐条一致，非回归：
  Windows 无 POSIX mode 位（`save → read round-trips and writes the file 0600`）、
  `os.homedir()` 不读 `HOME`（`resolveZhipuApiKey` 的 `$HOME` 回落用例）、
  Windows 符号链接语义（`survives a broken symlink inside .claude/`）、
  PATH / NVM / FNM / VOLTA node 解析（`node-resolver` 5 例）、
  外部工具链差异（`claude-context-resolver` host sync 2 例、`plugin-command-index` frontmatter、
  `plugin-expander-routing-bugs` customCwd 3 例），以及 1 例 `feishu-card` 的已知 5s 超时抖动
  （6777ms > 5000ms，单独重跑即通过）。
- `make typecheck` 干净（后端 + web 两侧 `tsc --noEmit` 均无报错）；
  `./scripts/check-stream-event-sync.sh` 直跑通过（`shared/` 四个真相源与三处副本一致）。
