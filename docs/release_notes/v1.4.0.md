# DeepThink v1.4.0 发布说明

> 自托管的多用户本地 AI Agent Loop Engineering 系统（支持桌面端 + 浏览器 + 移动端）
> Powered By AI Genius Institute，AI 光剑

发布日期：2026-09-23

v1.4.0 是一个**分布式能力落地 + 企业协作工作负载**版本。v1.3.0 把 DeepThink 的单机状态栈搬上了 K8s 云原生基座（Phase 1→Phase 3 的横向无状态化改造），但基座之上仍有一批能力停留在「单机可用、多 Pod 不可用」——配置读的是本地文件、工作区文件挂在本地磁盘、Agent 调度走的是进程内调用。**v1.4.0 的主轴就是把这些能力真正落到分布式基座上，并在此之上交付企业级协作工作负载**：

- **配置全量迁 PG + 工作区文件入 MinIO**：21 个配置域从本地文件迁到 `provider_configs` / `mcp_server_configs` 表，任意 Pod 可读；工作区文件同步到 MinIO `deepthink-workspaces` bucket，文件删除 / 移动 / 重命名 / 搜索 / 下载 / 预览全链路 S3 同步。
- **分布式 Agent 调度闭环**：修复分布式 agent-runner 调度的 4 类缺陷（关闭信号、订阅竞态、重复投递、BLPOP 延迟），修复 turnMounts（Skills / MCP / KB）在分布式分发前不生效、skill 跨 Pod 不可见、IM leader 选举竞态、`must_change_password` BIGINT 语义等一批 K8s 环境暴露的缺陷。
- **四大企业级业务面能力**：企业数字员工多人协作工作台、AgentNet Disk 企业级文件网盘、Eval Center 独立评测中心、Agent Group Chat（Swarm）多 Agent 群组协作 + Pipeline 可追溯执行面板。
- **平台能力收口**：Skills 入 PostgreSQL、对话挂载控件、办公快捷栏、Agent 对话挂载上下文 6 Bug 修复、运行轨迹持久化 + 执行概览摘要 + PDF 导出、Agent 流式输出与技能加载上下文修复。

本版本共 **46 个 commit**，schema 从 v59 演进到 **v70**。

## ✨ 新功能

### 一、K8s 分布式能力真正落地业务面（`k8s-distributed-storage`）

v1.3.0 解决了「服务能否多 Pod 跑起来」，v1.4.0 解决「跑起来之后，能力是否真的跨 Pod 可用」。此前多 Pod 环境下的真实症状是：Web UI 改完配置另一个 Pod 读不到、工作区文件只写在当前 Pod 的本地盘、Skills 挂载在调度到另一个 Pod 时丢失。本阶段分三层改造：

#### 1. 配置全量迁 PostgreSQL（`b4cd57a`）

- **21 个配置域**从本地文件迁移到 DB（`provider_configs` + `mcp_server_configs` 表），实行 **DB-first read**：任意 Pod 修改配置后，所有 Pod 立即可读。
- **工作区文件基础设施迁 MinIO**：新增 `deepthink-workspaces` bucket，工作区文件读写统一走对象存储，Pod 本地不再持有状态。
- Schema 演进 v63→v66。

#### 2. Phase 2 分布式存储：P1/P2 三项任务（`4defe24`）

- 覆盖配置迁移剩余的 P1（功能性阻塞）与 P2（一致性）任务。

#### 3. S3 同步接线全覆盖（`454e8c1`）

- 文件 **删除 / 移动 / 重命名 / 搜索 / 下载 / 预览** 六个操作全部接入 S3 同步，消除「DB 有记录、对象存储无对象」的中间态。

> **验证**：`docs/test_report/k8s-distributed-storage/TEST_REPORT.html`——2 副本 RollingUpdate、PG v66、MinIO bucket 就绪、Redis 7。26 项用例 **19 项 PASS（73.1%）**；其中 7 项失败全部是**测试脚本 API 路径与实现不匹配**（`/api/auth/status`、`/api/config/feishu` 等旧路径），非功能性缺陷 —— 报告 AC9 行对此有明确记录。9 条 AC 中 **AC1–AC8 全部 PASS**。

### 二、分布式 Agent-Runner 调度修复（`distributed-dispatch-fix`）

K8s 环境下 Agent 任务经 Redis 队列分发到 agent-runner Pod，本阶段修复调度链路上的 4 类缺陷（`481e646`、`7176cdc`）：

- **关闭信号丢失**：`_close` sentinel 在分布式路径未正确传递，agent-runner 无法优雅退出。
- **订阅竞态**：任务投递与订阅建立之间存在窗口，导致任务丢失。
- **重复投递（2× dup）**：同一 turnId 被 LPUSH 两次，Agent 重复回复。
- **BLPOP 延迟**：长轮询阻塞导致任务领取延迟。
- **Session resume** 在分布式模式下失效。

> **验证**：`docs/test_report/distributed-dispatch-fix/TEST_REPORT.html`——**6/6 PASS（100%）**。AC1 真实消息 → WS 回复；AC2 **16 个 stream event**（`thinking_delta` × 7、`text_delta` × 5、`usage` × 1、`status` × 3）；AC4 agent-runner 处理完回到 BLPOP 等待；AC5 `LLEN deepthink:agent-tasks` = 0；AC6 多 Pod 去重。

## 🐛 缺陷修复

- **Agent 群组发消息 500**（`0a04903`）：`SqliteError: no such table: group_messages`。根因是 Agent 群聊的 `group_seats` 与 `group_messages` 同属一个 v67 迁移块，但混入的 PG 专有语法 `ALTER TABLE … ADD COLUMN IF NOT EXISTS` 让 SQLite 迁移批处理**中途抛出**，第一张表建好、第二张表从未创建。修复 SQLite 迁移兼容性，详见 `docs/issues/2026-09-23-sqlite-add-column-if-not-exists-migration-abort.md`。
- **Disk 清空回收站 404**（`a12f67c`）：Hono 按注册顺序匹配路由，参数路由 `DELETE /:jid/files/:path` 先于字面路由 `DELETE /:jid/files/trash` 注册，`trash` 被当作 `:path` 捕获。修复为调整注册顺序。详见 `docs/issues/2026-09-11-disk-trash-route-priority.md`。
- **表名冲突**（`docs/issues/2026-09-11-table-name-collision.md`）。
- **Eval Center Drift 评分 `toFixed` 崩溃**（`7d8037b`）：详见 `docs/issues/2026-09-12-eval-center-drift-tofixed-crash.md`。
- **`includeInactive` 查询参数只接受 `'1'` 不接受 `'true'`**（`a1e0071`）。
- **`must_change_password` 在 PG 下恒为 true**（`docs/issues/2026-09-13-k8s-must-change-password-bigint.md`）：PG BIGINT 返回字符串，`!!row.must_change_password` 对 `'0'` 也为 true。
- **kind 节点镜像拉取失败**（`docs/issues/2026-09-12-kind-node-image-pull-broken.md`）。
- **`stop-prod` 在 logs 目录不存在时 `touch` 失败**（`207631a`）。
- **`start-prod` 一键重启**（`3da26fc`）：端口被占用时先自动停旧实例再增量编译并后台守护启动；`stop-prod` 主动停止不重启，意外退出由看门狗拉起。
