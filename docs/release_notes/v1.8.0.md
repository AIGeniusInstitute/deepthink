# DeepThink v1.8.0 发布说明

> 自托管的多用户本地 AI Agent Loop Engineering 系统（支持桌面端 + 浏览器 + 移动端）
> Powered By AI Genius Institute，AI 光剑

发布日期：2026-10-17

v1.8.0 是一个**能力边界扩张**版本，主轴是全新模块 **知识库（Knowledge Base）**：把腾讯开源的 WeKnora 知识库内核整体复刻到 DeepThink 原生的 TypeScript / React 栈上——文档切分为带**原文绝对字符偏移**的分块、分块级向量化、向量 + 关键词双路 RRF 融合检索，以及**带引用溯源**的 RAG 问答；并在同一版本内补齐**扫描件 OCR**与**系统内置开源向量模型服务**。

在此之前，DeepThink 的 Agent 能写代码、能跑 Loop、能被监控，但它**读不了企业自己的文档**：没有文档入库，没有检索，没有引用。Agent 的"知识"只能来自上下文窗口和它自己爬到的网页。企业最需要 Agent 掌握的那部分知识——制度、临床方案、运维手册、历史项目文档——恰恰都在本地。

本版本共 **33 个 commit**，**Schema v72 → v73**（新增知识库 6 张实体表 + 4 张 FTS5 / vec0 虚拟表），无破坏性 API 变更。

## 🎯 新能力：知识库子系统（WeKnora 复刻）

需求与技术方案见 [`docs/prd/2026-10-16-weknora-full-replica/`](../prd/2026-10-16-weknora-full-replica/)、[`docs/tech_solution/2026-10-16-weknora-full-replica/`](../tech_solution/2026-10-16-weknora-full-replica/)；导航入口「知识库」→ `/knowledge-bases`。

### 1. 检索内核：让「引用哪一个字的哪一段」可验证

复刻的**核心约束**不是"能搜到"，而是**每一条引用都能回到原文的确切位置**：

```
text.slice(chunk.startAt, chunk.endAt) === chunk.content
```

这条不变式写在分块器里、被单测与端到端用例逐块断言。它换来的能力是：检索结果里的引用可以**按偏移回源**到原文高亮，而不是给用户一段"大致在这里"的文字。没有它，`文档 ID + 页码`这种粗粒度引用在大纲结构的中文文档上基本无法核验。

| 层 | 实现 |
|---|---|
| 分块 | `src/kb/chunker.ts`：`heading` / `heuristic` / `recursive` 三策略 + **父子分块**（父块只用于命中后回溯上下文，**不进向量索引**） |
| 融合 | `src/kb/fusion.ts`：RRF，K=60，向量 0.7 / 关键词 0.3 |
| 检索 | `src/kb/search.ts`：`keyword` / `vector` / `hybrid` 三模式，双路得分与诊断信息原样返回给「检索测试台」 |
| 重排 | `src/kb/rerank.ts`：可选 cross-encoder，默认关闭；未配置即**不改动融合顺序** |
| 问答 | `src/kb/rag.ts`：流式 / 非流式，回答带编号引用，引用可展开看原文 |

**父子分块的口径**（容易误读，已在文档中明示）：当某个 section 的正文小于子块尺寸时，"父块 == 唯一子块"，**不产生父行**——这不是漏做，是 WeKnora 的语义。实测 `bodyRepeat=150` 的 6693 字夹具切出 42 块（14 父 + 28 子），`bodyRepeat=40` 的 2073 字夹具切出 14 块（0 父 + 14 子），两条都用独立用例锁定。

### 2. 检索增强：把"问不准"拆成五个可单独关闭的开关

| 子项 | 能力 | 默认 |
|---|---|---|
| 查询改写 / 扩展 | 纯本地生成变体，只作用关键词臂（向量臂不动），变体命中给救援分 | 关 |
| 查询理解 | 改写 + 意图识别，意图决定走 FAQ 桶还是文档桶 | 开 |
| FAQ 索引 | 标准问 / 相似问分别建向量，检索时分桶；**相似问带负向否决**（问的是相似问，不能把整条 FAQ 当答案给出去） | 库类型为 FAQ 时 |
| 预生成问题（Doc2Query） | 为分块预生成可能的提问并一并向量化，弥补"用户问法"与"文档写法"的措辞鸿沟 | 关 |
| 重排 | 可选 cross-encoder，候选上限 50 | 关 |

**默认关闭的项不是半成品**：全部有单测与 UI 验收，"关闭时不改变任何既有结果"本身也是被断言的。

### 3. 文档接入：11 种格式 + 四条入口

| 入口 | 说明 |
|---|---|
| 单文件上传 | 单文件 ≤ 100MB；`pdf / docx / pptx / xlsx / epub / xmind / html / csv / json / markdown / text` |
| URL 抓取 | 走 SSRF 防护链（字面量校验 → DNS 解析校验 → 逐跳重定向校验） |
| 手写 Markdown | 直接写正文，与上传共用同一条入库链路，**内容哈希判重口径一致** |
| 整目录 / 整包 | 目录选择（`webkitdirectory`）与拖拽目录（`webkitGetAsEntry` 递归）；`zip` 整包走服务端解包，**逐条回执** |

**zip 容器格式**（pptx / xlsx / epub / xmind）共用 `src/document-parser-zip.ts`：

- **pptx** 按 rels 页序输出（不是文件名序，实测夹具 `slides-reordered.pptx` 的文件名序与真实页序相反）
- **xlsx** 表头与行绑定成 Markdown 表格——按"单元格平铺"切块会一落刀就把剂量和药名拆开
- **epub** 按 `spine` 序（`toc` 顺序才与阅读顺序一致）
- **xmind** 层级转标题层级，游离主题（`children.detached`）不渲染

三条安全闸：条目数 ≤ 5,000、**解压前**按 `uncompressedSize` 累计 ≤ 200MB、拒绝路径穿越（`..` / 绝对路径 / NUL）。老二进制格式（`.doc/.xls/.ppt`，magic `D0 CF 11 E0`）给出**明确的"请另存为"提示**，而不是笼统的"不支持"。

### 4. 扫描件 OCR + 系统内置开源模型服务

需求原文：「扫描件要支持，9999 那个实例要配向量模型，直接系统内置部署使用开源的向量模型服务。」

**内置模型服务**（`src/local-model.ts`）：探测 / 拉起 / 流式拉取 / 维度探测。维度是**问出来的**而不是硬编码——`vec0` 建表时固定维度，写错要等第一次检索失败才暴露。

**扫描件 OCR**（`src/ocr.ts` + `src/kb/ocr-ingest.ts`）：纯图片 PDF 渲染成 PNG 交给视觉模型转写，表格按 Markdown 保留行列。光栅化用 `pdfjs-dist` + `@napi-rs/canvas`——两者都是既有依赖，**本轮没有新增任何 npm 依赖**。

三个必须踩过的坑，全部用实测数据定方案：

| 坑 | 实测 | 处理 |
|---|---|---|
| 思维链视觉模型烧光上下文 | `qwen3-vl:8b` 单页 51s～>300s，3 页夹具丢 1 页，287 页估算 6–12 小时 | 默认改用 `qwen2.5vl:7b`（单页 14–20s，3 页全中，287 页约 38 分钟） |
| Ollama 的 OpenAI 兼容端点**静默忽略** `options.num_ctx` | `/v1/chat/completions` 传 16384，`/api/ps` 仍是 4096 | 改走原生 `/api/chat` |
| 「截断」被当成「空白页」 | `done_reason=length` + 空正文被记为 `emptyPages`，**不报错** | 截断与空白分开判定，失败在正文留痕 |

OCR 必须后台跑（287 页 × 十几秒），但上传当场会校验"开关 / 服务 / 模型是否就绪"，不满足直接 400 指路设置页——**不让用户等半小时才看到失败**。

### 5. Agent 真正用得上：三个内置工具

`kb_search` / `kb_read_document` / `kb_list_documents` 注册进 Agent 运行时。知识库不是给人在网页上搜着玩的——它要能被 Agent 在任务执行中直接调用，否则仍然只是另一个文档管理后台。

### 6. 落地取舍（Think Before Coding：显式暴露）

| 决策 | 取舍 |
|---|---|
| **引用以字符偏移为准，不以页码为准** | 中文大纲文档的"第 3 段"无法核验；代价是分块器必须严格维持偏移不变式，任何后处理（如去空白）都不能偷偷改 content |
| **父块不进向量索引** | 检索单元是子块（更小、更准），父块只在命中后回溯上下文；代价是一次完整问答要读两次分块表 |
| **FAQ 与文档分桶** | FAQ 问的是"标准答案能不能命中"，文档问的是"正文哪一段相关"，混在一个桶里向量相似度会互相污染；相似问另做负向否决 |
| **OCR 只支持 PDF** | 光栅化依赖"页"的模型；epub / xmind / xlsx 没有页，强行走 OCR 只会得到一个错误——如实暴露边界 |
| **关键词臂是子串/短语语义**（FTS5 trigram） | 中文整句在纯 keyword 模式不命中，靠向量臂覆盖。这是已知边界，不是缺陷 |
| **失败分类要可见** | 目录 / 整包上传**绝不静默吞条目**：隐藏项、不支持格式、超上限，每一条都带 reason 出现在回执里 |

## 🐛 知识库线修复的缺陷（全部按 issue 工作流沉淀）

本版本新增 **19 篇** issue 复盘文档（`docs/issues/2026-10-1*.md`，8 节完整结构）。其中影响最大的几条：

| # | 现象 | 根因 | 为什么单测没拦住 |
|---|---|---|---|
| 1 | **「上传文档」按钮点了完全没反应**（用户上线实例上报） | `<button>` 被包在 `<label>` 里，规范要求 label 对 interactive content 后代的点击"什么都不做" | Playwright 的 `setInputFiles()` 直接给 input 赋值，**绕过了"点按钮"这一跳** |
| 2 | PDF 上传 100% 失败：`pdfParse is not a function` | `pdf-parse` v2 改成具名类导出，旧写法退化成模块命名空间对象 | PDF 解析**此前零覆盖** |
| 3 | 扫描件"上传成功、状态就绪"却检索不到任何东西 | `pageJoiner` 默认值给每页伪造 `-- n of 287 --` 标记，**空值守卫永远不触发** | 与 #2 同一函数，同样零覆盖 |
| 4 | 长文档尾部内容永远检索不到 | embedding 层对超长文本**静默截断** 8000 字符 | 用例都用短文档 |
| 5 | 中文关键词检索恒为 0 命中 | FTS5 `unicode61` + 整句短语匹配语义 | 用例用英文 token |
| 6 | 分块偏移与内容对不上，引用无法回源 | 分块后做了文本整理，offset 未同步 | 只断言了"块数 > 0" |
| 7 | 删除知识库必然 500 | `DELETE` 语句上误用 `.all()` | 删除路径无覆盖 |
| 8 | FAQ 条目建完不被向量化 | POST / PUT 未触发起始嵌入，FAQ 库也没有"重建索引"入口 | 只验了条目 CRUD 返回 200 |
| 9 | 纯标题文档（如 xmind）入库失败：`Chunking produced no chunks` | heading 分块逐段跳过空 body，**整篇只剩标题时一块不剩** | 被 xmind 解析器放大成必现 |
| 10 | 切一次页签后「上传目录」静默退化成普通文件框 | `webkitdirectory` 只在**首次挂载**的节点上打补丁，条件渲染会换节点 | 探针恰好跑在首屏 |
| 11 | `.html` 上传与 URL 抓取 100% 失败：`require is not defined` | ESM 运行时里用了 `require` | **vitest / tsx 的转换层会注入 `require` 兼容对象**，测试永远是绿的 |
| 12 | 重建索引后列表仍显示「已向量化 0」 | 冗余计数列只由 ingest 管线维护，rebuild 绕过了它 | 接口返回的 `attempted/success` 全都是对的 |
| 13 | **URL 入库存在 SSRF**，可被诱导读取云元数据 | `fetch` 只判了 `^https?://`，且 `redirect: 'follow'` | 安全用例此前没有 |
| 14 | `make start-prod` 服务的是**桌面版内置前端** | Makefile 启动路径优先用了桌面端 dist | 静态检查看的是源码，不是启动脚本 |
| 15 | `make stop-prod` 报「已停止」，几秒后旧看门狗又拉起来 | 停止时未先停看门狗 | 没人测过"停两次" |

**共性**：这 15 条里**没有一条**是靠"再读一遍代码"发现的。它们长在单测够不到的地方——**用户点得到吗、真实 ESM 运行时跑得通吗、接口返回 200 之后数字对不对**。这也直接改变了本版本的验收口径：

> **e2e 必须打在 `dist` 编译产物上**，并且「用户点得到」一律用 `waitForEvent('filechooser')` 真实点击，不用 `setInputFiles()` 绕过按钮。

## 📦 升级说明

- **Schema 自动迁移 v72 → v73**：启动时创建知识库 6 张实体表 + 4 张 FTS5 / vec0 虚拟表，**无数据改写、无破坏性变更**。
- **新增路由族** `/api/paas/knowledge-bases/*`（34 个端点：库 / 文档 / 分块 / FAQ / 检索 / 问答）。
- **新增页面**：「知识库」→ `/knowledge-bases` 与详情页（文档 / 分块 / 检索测试台 / 问答 / FAQ 五个页签）。
- **新增 Agent 工具**：`kb_search` / `kb_read_document` / `kb_list_documents`（随 Agent 运行时自动注册）。
- **向量化需要模型配置**：在「设置 → 模型服务」配置向量模型。**推荐直接用系统内置的开源模型服务**（本机 Ollama `bge-m3`），不需要任何外部 API Key。
- **扫描件 OCR 需要视觉模型**：同样是内置服务提供（`qwen2.5vl:7b`），配置 `ocr.json` 即可；未配置时上传扫描件会在**上传当场**被拒绝并指路设置页，不会静默入库噪声。
- **SQLite 需启用 sqlite-vec**：向量索引依赖 `sqlite-vec` 扩展（启动日志出现 `vector index enabled` 即正常）。
- **既有链路零改动**：知识库是完全新增的子系统，不影响对话 / 图编排 / Loop / 监督者 / 开放平台 / 运行监控。
